Why R?

What Is R?

A free tool built specifically for working with data.

  • Made by statisticians, for statistics
  • One of the best tools in the world for turning data into charts
  • Completely free, and always will be
  • Used by researchers, governments, and companies everywhere

Think of it like this

If Excel is a calculator, R is a full workshop — a bit more setup, but far more powerful once you know your way around it.

What Can You Build With R?

  • Charts
  • Documents
  • Analysis
  • Clean, publication-ready graphs
  • Interactive charts and maps
  • Reports and papers
  • Slide decks — like this one!
  • Websites and dashboards
  • Statistics and modelling
  • Tables that update automatically with your data

Your Workspace: RStudio

What Is RStudio?

The app where you’ll write and run R code.

Think of R as the engine and RStudio as the dashboard — RStudio makes R much easier to work with day to day.

A newer option: Positron

Posit (the makers of RStudio) also built a newer app called Positron. It works the same way, and everything in this course applies to both. We’ll use RStudio for now — feel free to explore Positron later, once you’re comfortable.

The Four Panes You’ll Use Every Day

1. Source (top-left) Where you write your code

2. Console (bottom-left) Where code actually runs

3. Environment (top-right) Shows the data you’ve loaded

4. Files / Plots / Help (bottom-right) Browse files, view plots, read help pages

Tip

Don’t worry about memorising this now — you’ll be comfortable with it after a day of using it.

Writing Code: Scripts vs. Documents

Two Ways to Write Code

R Scripts (.R)

Plain code, nothing else

library(tidyverse)
data <- read_csv("data.csv")
summary(data)

Good for: quick analysis, everyday work

Quarto Documents (.qmd)

Code and writing, together

## Results

The data shows...

```{r}
summary(data)
```

Good for: reports, papers, presentations

Why this matters

A Quarto document keeps your explanation and your code in one file, so your analysis and your write-up never fall out of sync.

Organizing Your Work: R Projects

The Problem: setwd()

Please avoid this ❌

setwd("C:/Users/YourName/Documents/My Research/Data")
data <- read.csv("survey.csv")

This path only exists on your computer. Move the folder, share it with a colleague, or switch machines — and it breaks.

The Fix: R Projects ✅

When you open an .Rproj file, RStudio automatically knows where “home” is — so paths like this work everywhere, on anyone’s computer:

data <- read_csv("data/survey.csv")
ggsave("figures/plot1.png")

The one rule to remember

Always work inside an R Project. It’s the single habit that saves the most future headaches.

Creating Your First Project

  1. File > New Project
  2. New Directory
  3. Choose a name and a location
  4. Click Create Project

Note

That’s it — RStudio reopens inside your new project, ready to go.

A Simple Way to Organize Files

my-project/
├── my-project.Rproj
├── data/
├── scripts/
└── figures/
  • Keep raw data separate — never edit it directly
  • Give scripts clear names
  • You can always add more folders as the project grows

Saving Your Work’s History: Git & GitHub

What today covers

Today is just the concepts — what Git is and why it’s worth learning. We’ll get fully hands-on together on Day 2/3.

The Problem Git Solves

Without version control:

thesis_final.docx
thesis_final_v2.docx
thesis_FINAL.docx
thesis_FINAL_actual.docx

😱 Which one is current?

With Git:

thesis.docx

✅ One file. Every past version is saved automatically, and you can go back to any of them, anytime.

Git vs. GitHub

Git

  • Runs on your computer
  • Saves snapshots of your work
  • Works even with no internet

GitHub

  • Lives online
  • A backup of your Git history
  • Lets others see your work and work with you

Tip

Think of Git as your personal diary, and GitHub as publishing that diary online.

Why Bother With Git?

  1. You never lose work — every saved version stays, forever
  2. You can see what changed — and undo it if you need to
  3. You can work with others — without emailing files back and forth

Note

Even working alone, Git is worth it — you’re collaborating with future you.

The Four Basic Steps

  • Stage — choose which changes to save
  • Commit — save them, with a short note
  • Push — send them to GitHub

Tip

We’ll practice this exact loop, step by step, on Day 2/3.

Setting Up Git (Once, Today)

git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"

Note

Use the same email you’ll use for your GitHub account.

Your First GitHub Repository

  1. Go to github.com/new
  2. Give it a name, e.g. r-practice
  3. Tick “Add a README file”
  4. Click Create repository

Tip

This is the online home for one project. You’ll create a new one for each new project going forward.

Bringing It Into RStudio

  1. File > New Project > Version Control > Git
  2. Paste your repository’s URL
  3. Choose where to save it
  4. Click Create Project

You now have a project connected to GitHub — ready for Day 2/3!

A Quick Word on Commit Messages

❌ "update"          ❌ "fixed stuff"
✅ "Add first draft of cleaning script"

Tip

Write the message for future you: what changed, in a few plain words.
